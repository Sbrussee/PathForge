# PathForge SISH comparison with upstream SISH

**Scope.** This is a code-level comparison of PathForge with
[mahmoodlab/SISH at `42fe005`](https://github.com/mahmoodlab/SISH/tree/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f), inspected on 2026-07-29. It focuses on the WSI VQ-VAE precompute path and the feature used for the Hamming-distance companion to the integer index. It is not a retrieval-quality benchmark.

## Summary

PathForge preserves the central SISH mechanism: the same encoder-only VQ-VAE architecture, semantic-codebook remap, three 2x2 average-pooling stages, integer construction, VEB predecessor/successor traversal, and uncertainty-based slide aggregation. It remains an **adaptation**, rather than a paper reproduction, while using foundation-model features instead of upstream DenseNet-121. PathForge now uses upstream adjacent-value binary packing and defaults the Hamming threshold to the upstream value of 128.

## Findings

| Severity | Difference | Evidence and consequence |
| --- | --- | --- |
| High | The companion descriptor is not equivalent. | Upstream extracts ImageNet-pretrained DenseNet-121 features and applies Yottixel adjacent-value/min-max binarization ([upstream `build_index.py` lines 114-134](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/build_index.py#L114-L134), [274-324](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/build_index.py#L274-L324)). PathForge now applies that same binary packing to the selected foundation-model row, but the underlying feature model remains different. Retrieval rankings therefore still require model-specific validation. |
| Resolved | Hamming default differed from upstream. | PathForge now defaults `hamming_thr` to `128`, matching upstream ([`database.py` lines 72-81](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/database.py#L72-L81)). It remains an exposed search hyperparameter for calibration. |
| High | Input-size compatibility with the released VQ-VAE is not enforced. | Upstream reads 1,024px at 20x and reads 2,048px then resizes to 1,024px at 40x ([`dataset.py` lines 52-69](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/dataset.py#L52-L69)). PathForge passes each stored tile read width/height straight to the VQ-VAE ([`sish_precompute.py` lines 712-741](../src/pathforge/slide_retrieval/search_strategies/strategies/sish/sish_precompute.py#L712-L741)). The shared VQ-VAE downsamples by 16 ([`sish_vqvae.py` lines 153-166](../src/pathforge/slide_retrieval/search_strategies/strategies/sish/sish_vqvae.py#L153-L166)); a non-1024 input therefore creates a different latent-grid geometry and key distribution. Require a SISH-specific 1024x1024 resize or explicitly validate the configured tile geometry before using the released checkpoint. |
| Medium | Mosaic selection is similar in form but not the same preprocessing pipeline. | Upstream first removes white/trash patches using an LBP logistic-regression model, then uses RGB-histogram K-means followed by spatial K-means at 5% per colour group ([`extract_mosaic.py` lines 36-67](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/extract_mosaic.py#L36-L67), [133-162](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/extract_mosaic.py#L133-L162)). PathForge's Yottixel-style representation clusters persisted mean RGB values and selects a configurable percentage, default `1.0`, without that SISH trash classifier ([`yottixel.py` lines 265-305](../src/pathforge/slide_retrieval/representation_strategies/strategies/yottixel.py#L265-L305)). This affects which patches receive VQ-VAE keys and companion features. |
| Medium | PathForge's VQ-VAE precompute is a useful cache, but its artifact is deliberately different. | Upstream writes latent maps plus coordinates to separate `LATENT/.../vqvae/*.h5` files ([`build_index.py` lines 137-180](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/build_index.py#L137-L180)). PathForge's CLI precomputes flattened, row-aligned VQ-VAE latents per slide/bag ([`retrieval_sish_vqvae.py` lines 74-93](../src/pathforge/cli/retrieval_sish_vqvae.py#L74-L93)) and reuses them from the retrieval H5 before converting to an index ([`sish_precompute.py` lines 238-320](../src/pathforge/slide_retrieval/search_strategies/strategies/sish/sish_precompute.py#L238-L320)). This is compatible with PathForge's artifact model and removes repeated WSI/VQ-VAE work, but is not file-format compatible with upstream's `LATENT` cache. |
| Low / no discrepancy | Core integer index and retrieval logic are preserved. | Both implementations use the semantic-codebook remap, three 2x2 average pools, and weights `1e6`/`1e11` for the integer key ([upstream `build_index.py` lines 77-111](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/build_index.py#L77-L111); [PathForge `sish_precompute.py` lines 50-84](../src/pathforge/slide_retrieval/search_strategies/strategies/sish/sish_precompute.py#L50-L84)). The default VEB traversal parameters also match: `C=50`, `T=10`, `pre_step=375`, `succ_step=375` ([upstream `database.py` lines 72-81](https://github.com/mahmoodlab/SISH/blob/42fe005413d7ae5b4e758a99505ecb0a2e6efb0f/database.py#L72-L81); [PathForge `sish_search.py` lines 164-170](../src/pathforge/slide_retrieval/search_strategies/strategies/sish/sish_search.py#L164-L170)). PathForge also retains the uncertainty cleaning/voting structure. |

## Recommended next checks

1. Treat the PathForge method as “SISH index + foundation-model Hamming companion”, not a faithful SISH replication.
2. Add an explicit SISH image-size policy (ideally resize to 1024x1024 before the released VQ-VAE) and record it in cache provenance.
3. Calibrate `hamming_thr` separately for each selected feature model and bit encoding; compare genuine-match and random-pair Hamming distributions before selecting a threshold.
4. If paper-level SISH reproduction is required, restore upstream's selection/trash filtering and DenseNet-121 min-max binarization, then validate retrieved rankings on a fixed slide set.
